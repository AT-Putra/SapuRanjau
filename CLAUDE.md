## graphify

This project has a knowledge graph at graphify-out/ with god nodes, community structure, and cross-file relationships. **This is a doc-driven (ADR-based) project** — the graph maps decisions (`docs/06`), concepts (GDD/ARCH), modules, and the 15 data entities (`docs/08`), not code.

Rules:
- For questions about the project (architecture, decisions, "what depends on X", "why was Y decided", how concepts/entities/modules relate), **first run `graphify query "<question>"`** when graphify-out/graph.json exists. Use `graphify path "<A>" "<B>"` for relationships and `graphify explain "<concept>"` for focused concepts. These return a scoped subgraph, usually much smaller than reading every doc.
- Read graphify-out/GRAPH_REPORT.md only for broad architecture review or when query/path/explain do not surface enough context.
- **Update graph berjenjang — JANGAN tiap edit. Ekstraksi = backend `openai` via 9router (`cx/gpt-5.6-sol`), BUKAN subagen, BUKAN Gemini.** Env sudah di `.claude/settings.local.json`. Graph per 2026-07-27 (pasca T-025): **921 node, 1132 edge, 2 node terisolasi, 86 komunitas**, dibangun sol seharga ~$0,3 dan 0 token Claude (kurasi subagen sebelumnya: 239 node/405 edge/~300k token). Biarkan `GEMINI_API_KEY` unset. Subagen = fallback kalau 9router mati. Tier per ukuran perubahan:
  - **T0** — typo/reword/tanggal/format, tanpa entitas/edge baru → **jangan sentuh graph** (0 token).
  - **T1** — 1–beberapa edge/atribut (tambah dependency, flip status task, tweak rationale) → **`python graphify-out/patch_edge.py add SRC TGT`** (patch `graph.json` langsung, ~0 token). `selftest` & `remove` tersedia. Node id: `docs_04_tasks_t_011`.
  - **T2/T3** — nambah/hapus entitas → **`python tools/graphify-extract-per-file.py --only <file basi…>`**, lalu `graphify cluster-only . --backend openai` + `graphify label . --backend openai`. **Pakai `--only`**: ekstrak hanya file yang isinya benar-benar berubah (~$0,03/file, ~2 menit/file) — memaksa 12 file cuma membakar uang dan memberi lebih banyak kesempatan variasi LLM menjatuhkan guard. Tanpa `--only` = seluruh korpus, ~$0,3/~25 menit. Guard anti-shrink per file bertoleransi 10% (`FLOOR_TOLERANCE`).
  - **JANGAN hapus `graphify-out/` untuk "rebuild bersih".** Tanpa graph di disk, graphify mengabaikan manifest dan mengekstrak seluruh korpus dalam satu pass → 65k token, 2 chunk, **980 → 295 node** (terbukti 2026-07-27). Isolasi per-file bergantung pada adanya graph lama.
  - **Guard yang menyala TIDAK cukup dipulihkan graph-nya saja** — graphify meng-cache hasil ekstraksi ber-kunci konten file, jadi hasil yang ditolak akan disajikan ulang tanpa memanggil LLM (`semantic cache: 1 hit / 0 miss`, `0 re-extracted`) dan gagal identik selamanya. Skrip sudah membuang entri cache iterasi yang gagal; kalau menambal manual, hapus juga `graphify-out/cache/semantic/**` untuk file itu.
  - **Sinkronkan manifest sebelum loop** (skrip sudah otomatis): loop mengisolasi satu file dengan mengeluarkan satu baris manifest, yang hanya benar kalau file lain dianggap tak berubah. Padahal kita mengekstrak justru karena dokumen berubah → iterasi pertama menyeret semuanya jadi mega-chunk.
  - `python tools/graphify-extract-per-file.py --selftest` — cek helper tanpa LLM/jaringan/kredensial.
  - **Dedup lintas-file jalan otomatis di akhir skrip** (`tools/graphify-dedup-crossfile.py`, deterministik, tanpa LLM) dan **harus diulang tiap ekstraksi**: tiap file memancarkan salinan ADR/task yang dikutipnya, jadi satu ADR bisa jadi 6 node. Peleburan memakai kunci tak-ambigu (kode ADR/T, nama file, label bertipe identik) dan mempertahankan label dari dokumen asal (ADR→`docs/06`, T→`docs/04`); frasa per-dokumen disimpan di atribut `aliases`. Terukur: 1005→867 node tapi link nyaris utuh (1102→1095), jangkauan query "board no-guess" 121→183 node.
  - **JANGAN `graphify extract .` polos.** Packing menjejalkan file sampai `--token-budget` (default 60k); seluruh korpus kita muat dalam SATU request → sol menjawab satu response untuk 7 dokumen → **graph runtuh 239 → 114 node** (terbukti 2026-07-27). Satu file per request wajib; itu tugas skrip di atas.
  - **JANGAN pula `--token-budget` kecil.** File >20.000 karakter (`_FILE_CHAR_CAP`) dipecah jadi FileSlice; kalau slice-nya tersebar ke beberapa chunk, sol kehilangan jejak path → id sampah `unknown_adr_0032`, `release_dokumen` (1 chunk = 0 rusak, 2 chunk = 3–33).
  - **`--no-gitignore` wajib.** Sejak 0.9.27 graphify membaca `.git/info/exclude` — tempat `docs/` disembunyikan dari GitHub. Tanpa flag ini docs tak terlihat, dianggap terhapus, dan graph di-prune (`Pruned 229 node(s)`). Konsekuensinya `.gitignore` tak dibaca, jadi artefak build dikecualikan di `.graphifyignore`.
  - **Patch prompt hilang tiap `uv tool upgrade graphifyy`** dan `tools/graphify-extract-per-file.py` **sudah memasangnya ulang sendiri** di awal run (idempoten, backup `.bak`, gagal-keras kalau anchor-nya hilang). Jalankan `python tools/graphify-patch-lang.py` manual hanya kalau memanggil `graphify` langsung. Prompt bawaan graphify tak punya aturan bahasa/kelengkapan/edge → tanpa patch: label diterjemahkan ke Inggris (id berubah → node duplikat), ekstraksi selektif (`docs/02`: 17 node vs 41 kurasi), dan 18% node menggantung tanpa edge.
  - **`GRAPHIFY_MAX_OUTPUT_TOKENS=32768` wajib** (nilai dari README graphify). Default backend openai 16.384, sedangkan dengan aturan COVERAGE output sol mencapai 20.116 token untuk `docs/06`. Kalau kelewat, graphify menandai `finish_reason="length"` lalu **membelah chunk** — persis pemicu id sampah di atas.
  - **Rasio edge ~1,26/node adalah plafon pipeline ini — jangan buang waktu menaikkannya.** Dua percobaan gagal 2026-07-27: `--mode deep` menghasilkan 0,99 edge/node (tak menolong), dan menuntut ~2 edge/node di prompt malah membuat sol menukar node jadi edge (136 node/138 edge → 100/111 — total edge ikut turun). Satu request hanya melihat satu file, jadi tautan lintas-dokumen memang tipis; kurasi subagen 1,69 tak tercapai. Butuh tautan spesifik? Pakai T1 `patch_edge.py` — manual, tepat sasaran, 0 biaya.
  - **Irama:** batch perubahan, update di *checkpoint* (akhir sesi ADR / fase selesai), **bukan per-commit**. Graph = cache navigasi; `docs/` = truth, boleh sengaja lag. Backup kurasi lama: `graphify-out/graph.json.bak-20260727`.

## Kotlin LSP (cclsp)

The `kotlin-lsp` MCP server (cclsp → JetBrains Kotlin LSP) gives **exact semantic navigation** for Kotlin code. Use it for *understanding*, Grep/Glob for *discovery*:

- Tracing where a symbol is defined, or finding all references to it → use `find_definition` / `find_references` (exact results) instead of Grep (text matches only). Also `get_hover` (type/signature/doc), `find_implementation`, `find_workspace_symbols`, and call-hierarchy tools.
- Use **Grep/Glob for discovery** (finding files, searching patterns/strings). Use **LSP for understanding** (definitions, references, type info).
- After locating a file with Grep/Glob, prefer LSP to navigate within it rather than reading the whole file.

Caveats (be honest about these): (1) the tools appear only after a **Claude Code restart** loads the MCP server; (2) kotlin-lsp is IntelliJ-based and **indexes on first use** — the first queries after startup can be slow or return partial results until indexing settles (cclsp logs an "initialization timeout, proceeding anyway" that is usually benign); (3) **correctness is still confirmed by compiling/testing** (`gradle compileKotlin` / tests) — LSP hints don't replace the build. Config: `.mcp.json` + `cclsp.json` (kt/kts → `tools/kotlin-lsp/bin/intellij-server.exe --stdio`).
